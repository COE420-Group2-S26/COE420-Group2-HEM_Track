# Initial Feasibility Study

**Technical Feasibility**

The system is designed to be made using standard web development tools and not any specialized software or hardware. The system can be built using open source tools as well. Thus, the system is technically feasible assuming that the time budget is allocated fairly to account for any unfamiliar tools.

**Economic Feasibility**

All the tools we plan to use for frontend, backend, and database development are free and open source, so we don't have any software costs. For the demo we can use free hosting or run it locally on our laptops, so there's no cost there either. A small limitation is that free hosting tiers can have restrictions, but this is acceptable since the demo does not require full-scale hosting.

**Operational Feasibility**

From research, we found that manually tracking equipment is a well-defined problem which HEM-Track specifically addresses. Intended users are most likely to use the system if our system is simpler and more convenient to use than a manual process.

**Schedule Feasibility**

The number of features we're planning is small enough to fit into the increments we already have for the remaining labs. Our plan is to first build a basic working version of the equipment registry, and then add the other features on top of that. Given the time left in the course, this seems realistic to achieve. Overall, the schedule seems feasible as long as we stick to this incremental plan.

**Overall Feasibility**

Based on the technical, economic, operational, and schedule feasibility analysis, our HEM-Track system is overall feasible. The major constraints are mainly R1, R2, R3, R4, and R5 as identified in the risk table. However, we have addressed them through the mitigation strategies to reduce or eliminate any effect they would have on the successful completion of the project.
