The Incremental Model would be the best fit for our project as it allows us to deliver a core feature before adding more. For example, the first increment for this project could be an inventory registry of all hospital equipment, allowing for operational utility from the beginning. In further increments, we could add features such as tracking, automated alert notifications or quick log checks. Additionally, the healthcare field requires reliability and compliance verification, which each increment goes through.

One drawback is that this model requires immediate architecture planning so that each increment shares a stable core architecture and data model. The best way for the team to handle this would be to document a shared data model and module interfaces before coding starts. Another drawback is that there is possible scope drift, leading to an inevitable failure of the project. To avoid this, we will fix the increment order:

1. Equipment Registry
2. Tracking
3. Reminders
4. Logging & Search
